# Шаблоны писем

Каждый шаблон — чистая функция, которая принимает данные письма и возвращает `MailTemplate`: тему, HTML и текстовую версию. Данные из БД и вложения готовятся в сервисе отправки.

- `layout.template.ts` — общая оболочка, логотип, адаптивные стили и подвал.
- `completed-order.template.ts` — оформленный заказ с карточками схем, выбранными размерами, подбором и итогом.
- `email-login.template.ts` — письмо со ссылкой для входа без пароля.
- `registration.template.ts` — подтверждение регистрации нового аккаунта.
- `mail-template.ts` — контракт шаблонов, экранирование HTML и форматирование цен.

Верстка использует таблицы и встроенные стили. Динамический текст нужно пропускать через `escapeHtml`.

Изображения подключаются через CID-вложения из `../mail-assets.ts`. Логотип берётся из `apps/am-front/src/public/assets/amstore logo.svg`, копируется сборкой в `mail/assets` и преобразуется в PNG. Превью схем преобразуются в JPEG из публичной папки uploads; при отсутствии файла карточка показывает текстовую заглушку.

При оформлении и повторной отправке заказа к письму прикладываются доступные CBB и PDF выбранных размеров. Проверки состояния заказа, его позиций, размеров и файлов общие с ручкой скачивания. Каждый файл прикладывается один раз по ID, с исходным именем; PNG не прикладывается. Nodemailer читает вложения с диска потоком через `path`. Если файл указан во вложениях, но недоступен на диске, отправка завершается ошибкой.

Общий `MailService` использует Mailpit на `127.0.0.1:1025` при `NODE_ENV=dev`. Для отправки через SMTP задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, при необходимости `SMTP_USER` и `SMTP_PASSWORD`, а также `MAIL_FROM`. В других окружениях отправка доступна только с настроенным SMTP.

`SITE_URL` задаёт адрес фронтенда для ссылок в письмах (в dev по умолчанию `http://localhost:4400`, в других окружениях требуется HTTPS). `EmailLoginService.createLink(userId, redirectPath)` создаёт одноразовую ссылку на любую локальную страницу сайта сроком на 7 дней. В БД хранится только SHA-256 токена. Токен передаётся во fragment URL и обменивается на обычную сессию через POST, после чего удаляется из адресной строки.

В письме с покупкой кнопка «Открыть заказ» ведёт на личный заказ покупателя. Ссылка выдаётся только для активного владельца, чей текущий email совпадает с получателем письма. При повторной отправке создаётся новая ссылка; прежняя действует до использования или истечения срока.

Публичные запросы входа и регистрации возвращают одинаковый `204` с пустым телом для существующих, неизвестных и неактивных аккаунтов. Обработчик HTTP только записывает задание в `users.auth_email_request_entity`: проверка пользователя и SMTP выполняются фоновым `AuthEmailService`. Это исключает различие времени и статуса ответа из-за существования аккаунта или ошибки доставки. Перед запуском новой версии примените миграции (`npm run am:back:typeorm:migration:run`). Дополнительный брокер сообщений не требуется.

Обработчик забирает до 10 заданий за проход, запускается раз в секунду, использует `FOR UPDATE SKIP LOCKED` и аренду на 10 минут для совместной работы нескольких экземпляров приложения и восстановления после перезапуска. SMTP ограничен таймаутами. После ошибки выполняется до пяти попыток с паузами 1, 2, 4 и 8 минут; ошибка не попадает в ответ API. В логах остаётся ID задания и номер попытки без адреса, токена и текста ошибки SMTP. После успеха, пяти неудач или истечения 24 часов задание удаляется вместе с email и хешем пароля. Сбой между доставкой и удалением задания может привести к повторному письму.

При недоступной БД обработчик увеличивает паузу между обращениями с 5 секунд до минуты и автоматически продолжает работу после восстановления. В лог попадает только безопасный код ошибки. Коды PostgreSQL `42P01` (нет таблицы) и `42703` (нет колонки) сопровождаются подсказкой применить миграции; SQL, параметры запроса и исходный текст исключения не выводятся.

Ограничения регистрации и входа общие и хранятся в PostgreSQL: для нормализованного email — 3 запроса за 15 минут и 10 за сутки; для IP — 20 за 10 минут и 100 за сутки. Счётчики учитывают все адреса независимо от существования аккаунта и сохраняются при перезапуске. При превышении API возвращает стандартный `429 TOO_MANY_REQUESTS` и `Retry-After`. В таблице лимитов хранятся SHA-256 ключей, без исходных email и IP. За reverse proxy настройте `TRUST_PROXY` только для доверенных адресов: IP берётся из Express, произвольный `X-Forwarded-For` не используется напрямую.

При запросе входа письмо отправляется только активному существующему пользователю. При регистрации неизвестного адреса отправляется одноразовое подтверждение на 7 дней, а аккаунт с хешем указанного пароля создаётся только при использовании ссылки, в одной транзакции с созданием сессии. До подтверждения войти с указанным паролем нельзя — иначе регистрация раскрывала бы существование аккаунта через последующий вход. Для существующего аккаунта регистрация отправляет обычную ссылку входа и не меняет пароль, роль, покупки или профиль; это относится и к аккаунтам без пароля, созданным заказом. При гонке подтверждений или создании аккаунта заказом существующие данные также сохраняются.

Для локального просмотра выполните `npm run am:mail:preview`. Необязательный аргумент — путь к превью схемы внутри uploads: `npm run am:mail:preview -- uploads/public/images/preview/example.webp`. Команда создаёт HTML, текстовую версию и `.eml` в `/tmp/amstore-order-email`, без отправки письма и без приватных файлов заказа.
