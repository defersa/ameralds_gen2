# Полные возвраты (AMS-13)

Приложение создаёт только возврат всего заказа на точную сумму исходного успешного платежа.
API, аудит и административный интерфейс описаны в [AMS-14](../order/admin/PLACED-ORDERS.md).

Миграция `1795000000000-external-refunds` сохраняет историю локальных операций, добавляет
происхождение `application/provider`, nullable инициатора для внешних возвратов, журнал
`users.refund_incident` и план обнаружения на платеже. Откат запрещён при наличии внешней истории.
Основную БД тесты не изменяют; миграцию нужно применить штатной командой перед запуском новой версии.

## Обнаружение и применение

`RefundDiscoveryService.observe` получает результат только после серверного чтения API провайдера.
Webhook проверяет подпись, затем читает `getRefund`. Неизвестная операция сопоставляется с исходным
успешным платежом по provider/externalId; клиентские суммы, идентификаторы и статус не подтверждают возврат.

Отдельный cron каждую минуту арендует до 20 успешных платежей и вызывает `listRefunds`.
Возрастного отсечения нет, следующий полный обход успешного платежа запланирован через час;
при ошибке возможен повтор после минутной аренды. Адаптер обязан вернуть полный список,
самостоятельно обойдя все страницы, либо отклонить запрос. Ошибка одной операции не мешает обработать остальные.
Внешние HTTP-вызовы ограничены десятью секундами и выполняются без DB-lock.

Обнаруженный полный возврат сохраняется с origin=provider и initiatedBy=null. Его первичный статус
unknown обеспечивает восстановление после сбоя между обнаружением и финализацией. Создание нового
финансового запроса для него не выполняется. Потерянный ответ локального запроса восстанавливается по UUID.

Общий обработчик `RefundResultService` атомарно устанавливает REFUNDED, отзывает только основания заказа
и ставит уведомление в outbox. Платёж сохраняет SUCCEEDED. Отказ сохраняет права, неопределённость
не разрешает новый финансовый запрос, повторные события не восстанавливают права.

## Расхождения

Частичный внешний возврат, несовпадение валюты/суммы или конфликт с другой операцией сохраняются
в журнал финансовых инцидентов по уникальной паре provider/externalId. Сохраняются исходный платёж,
заказ, фактические сумма/валюта, состояние провайдера, время и вид расхождения. Повтор обновляет
время наблюдения и состояние провайдера, не создавая копий и не меняя исходные суммы и привязку.
Подтверждённый успех не понижается поздним событием.

Инцидент виден только администратору и блокирует слепой полный возврат. Заказ не признаётся
полностью возвращённым и права автоматически не отзываются. Автоматическое разрешение,
произвольные суммы и ручные финансовые действия не добавлены: решения фиксируются в AMS-16.

## Покупатель

История и детали возвращают `refund` с безопасными status/amount/currency/completedAt последней
операции. Инициатор, причина, внешние ID, ключи и инциденты не попадают в пользовательский DTO.
Для accepted/processing/unknown показывается обработка; только подтверждённый успех означает «Возвращён».
Открытая страница опрашивает незавершённый возврат раз в пять секунд до двух минут;
затем доступна ручная проверка. История опрашивается только при наличии незавершённого возврата.
Смена маршрута/выход отменяют подписки. После подтверждения детали обновляют эффективные права и корзину.

## Проверки

`admin-placed-orders.postgres.spec.ts` проверяет настоящую миграцию в одноразовой PostgreSQL-базе,
конкурентные возвраты, внешний webhook, пропуск webhook, старые платежи, частичный инцидент,
запрет слепого повтора, сохранение доступа, rollback и восстановление после внешнего успеха.
Unit-тесты покрывают обработку и отказ; frontend-тесты — состояния покупателя, опрос, ошибку/повтор,
отмену запроса при выходе и административный просмотр инцидента.

Реальный провайдер и production-интеграция — AMS-15. Mock работает только в dev/test и не хранит
внешнее финансовое состояние после перезапуска; реальные списания при тестах не выполняются.
