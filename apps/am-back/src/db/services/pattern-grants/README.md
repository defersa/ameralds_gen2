# Основания цифровых прав (AMS-11)

`UserPatternGrantEntity` — журнал выдач и отзывов. Одна строка предоставляет
один размер конкретной схемы (`size:<patternSizeId>`) либо цвет всей схемы
(`color`, без размера). Право действует, пока `revokedAt = NULL`.

`UserPatternEntity` остаётся совместимым представлением объединения действующих
оснований для корзины, checkout и профиля. Это не второй независимый источник
владения: изменять его напрямую после миграции нельзя. `PatternGrantsService`
атомарно обновляет журнал и пересобирает только затронутые схемы. Дубли старых
строк владения деактивируются, а их основания сохраняются. Пустое владение
становится неактивным.

## Источники и миграция

Перед запуском применить `1794100000000-user-pattern-grants` обычной командой
`npm run am:back:typeorm:migration:run`.

Источники: `order` и `admin_order` с конкретными `orderId` / `orderItemId`,
либо `legacy` с ID прежней строки `UserPatternEntity`. Повтор выдачи одного
размера/цвета одной позиции блокируется уникальным индексом, включая ранее
отозванные основания. Новый источник может независимо предоставлять то же право.

Миграция переносит каждую существующую строку владения как legacy-основание:
прежняя модель агрегировала несколько покупок и не позволяет достоверно приписать
размер или цвет одному историческому заказу. Выдуманная привязка могла бы отозвать
лишние права при возврате. Неактивное владение сохраняется в журнале с отзывом
`legacy_inactive`. Строки без пользователя или схемы остаются в старой таблице,
но не предоставляют доступ. Размер другой схемы не импортируется.

Существующие административные и исторические покупки сохраняют доступ.
Новые административные покупки вызывают ту же выдачу после создания оплаченной
личной копии заказа; основание привязано к позиции этой копии. Исторические
неизвестные суммы не восстанавливаются из каталога.

Исторические ID схемы/размера сохраняются в журнале и после удаления каталога.
Доступ требует существующего активного каталога, а пересборка проекции не
восстанавливает удалённые записи. Источники выдачи защищены внешними ключами;
триггер запрещает удаление журнала, перепривязку прав и изменение первого отзыва.
Откат миграции разрешён только до первой новой выдачи или отзыва, чтобы не потерять
историю, которую невозможно представить прежней моделью.

## Транзакционные методы

`PatternGrantsService` экспортируется через `DbInfrastructureModule`.
Репозитории остаются внутренними. Методы требуют активный `EntityManager`:

```typescript
await dataSource.transaction(async (manager) => {
    // Будущий обработчик AMS-12 сначала проверяет финансовое списание и фиксирует
    // PAID / paidAt. Эта операция сама оплату не подтверждает.
    await grants.grantPaidOrder(userId, orderId, manager);
});
```

`grantPaidOrder` проверяет владельца и оплаченный источник, выдаёт только опции
snapshot позиции, включая исторические ID удалённых схем и размеров. Изменение
каталога между checkout и оплатой не препятствует записи оплаченных оснований;
удалённые или перепривязанные размеры не открывают скачивание. Триггер БД проверяет
каждое право по snapshot, а не по текущим связям каталога. Административный
legacy-источник без snapshot использует прежний активный состав и живые связи.
Повтор не восстанавливает отозванное основание. Текущие цены каталога и переданные
клиентом флаги владения не используются.

Порядок блокировок: пользователь → заказ → журнал/проекция. Он согласован
с корзиной, checkout и оплатой. Выдача прав и изменение заказа откатываются
вместе при ошибке вызывающего обработчика.

`revokeSelected(actorId, input, manager)` проверяет активную роль администратора
по БД. Владелец должен существовать, но может быть деактивирован: подтверждённый
возврат отзывает доступ до возможного восстановления аккаунта. Новая выдача
по-прежнему требует активного владельца. Область отзыва — одна позиция одного заказа либо одна явно выбранная
legacy-покупка. Все `grantIds` обязаны принадлежать указанным владельцу и источнику;
подмешивание постороннего ID отклоняет операцию целиком.

Для заказа до вызова должен быть подтверждён возврат и зафиксирован статус
`PARTIALLY_REFUNDED` или `REFUNDED`. Обязательны непустые `reason` и
`refundReference` — ссылка на подтверждённый финансовый результат. Для legacy
администратор явно выбирает исторические основания и указывает документальное
подтверждение. Сам сервис не обращается к провайдеру и не проверяет внешнюю ссылку:
это обязанность будущего доверенного обработчика возвратов, а не клиентский ввод.
Публичного endpoint для отзыва нет.

При повторном отзыве сохраняются исходные время, причина, автор и ссылка.
Другие основания того же размера/цвета не изменяются. Для новой выдачи после
отзыва требуется новый источник; изменение отозванной строки запрещено.

## Покупка, цвет и скачивание

Корзина и checkout продолжают использовать `getBoughtSelections`: действующие
размеры и цвет исключаются из покупки; докупить цвет отдельно можно при наличии
хотя бы одного размера. Без размеров цвет покупается вместе с новым размером.

После отзыва последнего размера право на цвет сохраняется активным, со всей
историей. Повторно продавать цвет нельзя, но скачивание цвета приостановлено,
пока пользователь не получит хотя бы один действующий размер этой схемы.
Новый размер снова открывает ранее приобретённый цвет независимо от источника.

`GET /api/patterns/:id/download/:fileId` требует `@Auth()` и проверяет эффективное
владение текущего пользователя. Разрешены CBB/PDF/PNG действующего размера или
файл цвета при наличии права на цвет и любого действующего размера. Проверяются
активность пользователя, схемы, размера, определения размера, файла и связь
размера со схемой. Чужой/неактивный/отозванный материал возвращает `NOT_EXIST`
без раскрытия пути. Статус последнего заказа сам по себе доступа не даёт.
Прямое скачивание приватных файлов по ID остаётся административным.

## Проверки

```sh
npx nx run am-back:test --runInBand --testPathPatterns='pattern-grants|user-pattern.service|purchased-pattern-files'
GRANTS_TEST_DATABASE_URL=postgres://user:password@localhost:5432/postgres \
  npx nx run am-back:test --runInBand --testPathPatterns=pattern-grants.postgres
```

PostgreSQL-тесты создают отдельную случайную БД `ams11_test_*` и удаляют её после
проверок. Исходная БД подключения не изменяется; требуется право CREATE DATABASE.
Покрываются импорт/up/down, несколько источников, конкуренция, повторная выдача
и отзыв, откат транзакции, границы доступа и сохранение цвета без размеров.

Webhook, финализация успешной оплаты, финансовые возвраты, провайдер и админский
интерфейс возвратов остаются задачами следующих этапов.
