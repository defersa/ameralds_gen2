# Инструкции для фронтенда

Эти правила применяются к `apps/am-front` и его подкаталогам и дополняют [общие инструкции проекта](../../AGENTS.md). Перед каждой задачей в этой части проекта перечитывай этот файл.

## Подготовка

- Фронтенд — Angular в общем Nx workspace. Команды ниже выполняются из корня репозитория.
- Перед изменениями изучи затронутые компоненты и существующие решения в `src/app/cdk`, `src/app/shared` и `src/app/services`.

## Авторизация и роли

- Используй сигнал `AuthService.auth` как источник состояния авторизации. Текущее значение читай вызовом `authService.auth()`.
- Используй сигнал `ProfileService.isAdmin` как источник признака администратора. Текущее значение читай вызовом `profileService.isAdmin()`.
- В компонентах, guards и прикладных сервисах используй эти сигналы для проверок авторизации и роли. Хранение токенов и загрузку профиля оставляй существующим сервисам `AuthService` и `ProfileService`.
- Производное состояние, включая выбор корзины в `MajorCartService`, вычисляй через `computed`. Для реакций на вход, выход и изменение роли используй существующие реактивные подходы проекта, чтобы состояние обновлялось при изменении сигналов.
- Пользовательские запросы выполняй при `authService.auth()`, административные — при `authService.auth() && profileService.isAdmin()`.

## Стили и темизация

- Для простых стилей используй готовые классы Tailwind: раскладка, отступы, размеры, выравнивание и простая адаптивность. Не создавай отдельные CSS-классы для того, что понятно выражается готовыми утилитами.
- Темизацию и стилизацию основывай на общих переменных, функциях и миксинах проекта. Основные источники находятся в `apps/am-front/src/app/styles`:
  - `theming-var.scss` — палитры, функция `get-amstore-color` и общие переменные темы;
  - `spacing.scss` — шкала отступов и функция `get-spacing`;
  - `typography.scss` — миксин `get-amstore-font`;
  - `utils.scss` — миксины адаптивности, теней, границ и ссылок.
- Учитывай общие стили и классы из `apps/am-front/src/styles.scss`. Цвета, типографика и оформление должны соответствовать теме проекта, в том числе при использовании Tailwind.
- Если общей переменной, миксина или готового класса не хватает, добавь необходимое в соответствующий общий файл. Повторно используемые значения и оформление должны иметь общий источник.
- Для уникального визуала, который слишком сложно или неудобно выразить готовыми классами, используй собственные классы и локальные стили конкретного компонента.
- В локальных стилях также используй общие переменные и миксины. Не дублируй палитры, шкалы отступов и брейкпоинты произвольными значениями.

## Работа с кодом

- Переиспользуй существующие компоненты `amstore-*` и сервисы. Общие элементы интерфейса размещай в `shared`, базовые элементы — в `cdk`.
- Следуй существующим подходам Angular в соседнем коде: standalone-компоненты, сигналы и внедрение зависимостей через `inject`.

## Форматирование Angular-шаблонов

- Применяй правила при создании и изменении внешних HTML-шаблонов и inline `template` компонентов.
- Отделяй соседние HTML-элементы с внутренним содержимым одной пустой строкой на каждом уровне вложенности. Это относится и к коротким элементам с текстом или интерполяцией.
- Отделяй блоки Angular control flow (`@if`, `@else if`, `@else`, `@for`, `@empty`, `@switch`, `@case`, `@default`, `@defer` и связанные ветви) от соседних элементов и других блоков одной пустой строкой.
- Соседние ветви `@if`, `@else if` и `@else`, а также `@for` и `@empty` разделяй пустой строкой: закрывающая `}` предыдущей ветви и начало следующей ветви должны находиться на отдельных строках.
- Не записывай блоки control flow вместе с их содержимым в одну строку. Содержимое размещай с отступом на следующих строках.
- У всех тегов с содержимым открывающий тег, содержимое с отступом и закрывающий тег размещай на отдельных строках. Даже короткий текст или единственную интерполяцию внутри `h3`, `p`, `span`, `li`, кнопок и других элементов начинай с новой строки; не записывай такие элементы целиком в одну строку. Дополнительные пустые строки сразу после открывающего тега и перед закрывающим тегом не требуются.
- Сохраняй значимые пробелы в текстовых фрагментах и содержимое `pre`/`textarea`; форматирование не должно менять отображаемый текст.
- Пример разметки основан на [странице корзины](src/app/features/main/store/pages/cart/cart.component.html). При форматировании изменяемого участка используй правила выше; существующий файл может содержать ещё не приведённые к ним участки.

```html
<h2>
    Корзина
</h2>

@if (isAdmin()) {
    <amstore-cart-action-admin/>
}

@else if (auth()) {
    <amstore-cart-action-auth/>
}

@else {
    <amstore-cart-action-no-auth class="my-4 block"/>
}

<div class="flex flex-col gap-1">
    <span>
        Стоимость
    </span>

    <h2>
        {{ cartPrice()?.ru ?? 0 | number }} {{ currency() }}
    </h2>
</div>
```

## Команды и проверка

| Задача | Команда из корня репозитория |
| --- | --- |
| Запуск фронтенда на порту 4400 | `npm run am:front:start` |
| Сборка для разработки | `npx nx run am-front:build:development` |
| Production-сборка | `npm run am:front:build` |
| Линтер | `npm run am:front:lint` |
| Тесты | `npm run am:front:test` |
| Генерация API-клиента | `npm run am:front:generate:api` |

- Команда генерации сначала создаёт свежую Swagger-схему из текущего кода бэкенда в `dist/openapi/schema.json`, затем обновляет `src/app/api-v2` и закрывает временное Nest-приложение. Работающий бэкенд и БД не требуются.
- Для изменений шаблонов проверяй Angular-сборку, для изменения логики — затронутые тесты.
- Для изменений интерфейса проверяй адаптивность. Если проверка в браузере недоступна, явно сообщи об этом.
