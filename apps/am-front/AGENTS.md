# Инструкции для фронтенда

Эти правила применяются к `apps/am-front` и его подкаталогам. Перед каждой задачей в этой части проекта перечитывай этот файл.

## Подготовка

- Отвечай на русском языке.
- Фронтенд — Angular в общем Nx workspace. Команды ниже выполняются из корня репозитория.
- Перед изменениями изучи затронутые компоненты и существующие решения в `src/app/cdk`, `src/app/shared` и `src/app/services`.
- Перед запуском dev-сервера проверь, не запущен ли он уже. Используй работающий экземпляр, если он подходит для задачи.
- Если задача затрагивает бэкенд, прочитай также `apps/am-back/AGENTS.md`.

## Стили и темизация

- Для простых стилей используй готовые классы Tailwind: раскладка, отступы, размеры, выравнивание и простая адаптивность. Не создавай отдельные CSS-классы для того, что понятно выражается готовыми утилитами.
- Темизацию и стилизацию основывай на общих переменных, функциях и миксинах проекта. Основные источники находятся в `apps/am-front/src/app/styles`:
  - `theming-var.scss` — палитры, функция `get-amstore-color` и общие переменные темы;
  - `spacing.scss` — шкала отступов и функция `get-spacing`;
  - `typography.scss` — миксин `get-amstore-font`;
  - `utils.scss` — миксины адаптивности, теней, границ и ссылок.
- Учитывай общие стили и классы из `apps/am-front/src/styles.scss`. Цвета, типографика и оформление должны соответствовать теме проекта, в том числе при использовании Tailwind.
- Если общей переменной, миксина или готового класса не хватает, добавь необходимое в соответствующий общий файл. Повторно используемые значения и оформление должны иметь общий источник.
- Для уникального визуала, который слишком сложно или неудобно выразить готовыми классами, используй собственные классы и локальные стили конкретного компонента.
- В локальных стилях также используй общие переменные и миксины. Не дублируй палитры, шкалы отступов и брейкпоинты произвольными значениями.

## Работа с кодом

- Переиспользуй существующие компоненты `amstore-*` и сервисы. Общие элементы интерфейса размещай в `shared`, базовые элементы — в `cdk`.
- Следуй существующим подходам Angular в соседнем коде: standalone-компоненты, сигналы и внедрение зависимостей через `inject`.
- `src/app/api-v2` генерируется из OpenAPI. Изменения контракта вноси в DTO и контроллеры бэкенда, затем обновляй клиент генератором.

## Команды и проверка

| Задача | Команда из корня репозитория |
| --- | --- |
| Запуск фронтенда на порту 4400 | `npm run am:front:start` |
| Сборка для разработки | `npx nx run am-front:build:development` |
| Production-сборка | `npm run am:front:build` |
| Линтер | `npm run am:front:lint` |
| Тесты | `npm run am:front:test` |
| Генерация API-клиента | `npm run am:front:generate:api` |

- Генератор API использует схему `http://localhost:3000/swagger/schema`; для него нужен работающий бэкенд в dev-режиме.
- После изменения кода запускай проверки, соответствующие задаче. Для изменений шаблонов проверяй Angular-сборку, для изменения логики — затронутые тесты.
- Для изменений интерфейса проверяй адаптивность. Если проверка в браузере недоступна, явно сообщи об этом.
